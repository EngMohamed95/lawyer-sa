## المبدأ الحاكم

**البنية الحالية صحيحة وتبقى كما هي حرفياً.** هذه الميزة تُحصّنها وتُكمّلها فقط.

```
SUPER_ADMIN  ──────────────────────────────────────────┐
  صفحة /app/lawyers        → إدارة حسابات العملاء (المكاتب)
  صفحة /app/subscriptions  → طلبات وتجديدات الاشتراك
                                                        │
LAWYER (العميل = مدير المكتب)  ←────────────────────────┘
  صفحة /app/office-lawyers → إنشاء وإدارة محامي المكتب
  صفحة /app/trainees       → إنشاء وإدارة المتدربين
  + شاشة جديدة "فريق المكتب" تجمع كل الأدوار
```

## المتطلبات

### R1 — كل عمليات الحسابات تنتقل للخادم
Endpoints جديدة عبر Admin SDK (تُستبدل النداءات في نفس الشاشات، والشاشات تبقى كما هي):

| المسار | من يستخدمه |
|---|---|
| `POST /api/admin/tenants` | `SUPER_ADMIN` — إنشاء حساب عميل (مكتب) |
| `PUT /api/admin/tenants/:uid` | `SUPER_ADMIN` — تعديل بيانات المكتب والباقة |
| `POST /api/admin/tenants/:uid/renew` | `SUPER_ADMIN` — تجديد الاشتراك |
| `POST /api/admin/tenants/:uid/suspend` · `/activate` | `SUPER_ADMIN` — إيقاف/تفعيل |
| `DELETE /api/admin/tenants/:uid` | `SUPER_ADMIN` — حذف ناعم + تعطيل Auth + تعطيل كل مستخدمي المكتب |
| `POST /api/admin/tenants/:uid/impersonate` | `SUPER_ADMIN` — دخول للدعم الفني (مسجَّل إجبارياً) |
| `POST /api/office/users` | `LAWYER` — إنشاء مستخدم في مكتبه بأي دور من الأدوار السبعة |
| `PUT /api/office/users/:uid` | `LAWYER` — تعديل بيانات/دور مستخدم مكتبه |
| `POST /api/office/users/:uid/suspend` · `/activate` | `LAWYER` |
| `DELETE /api/office/users/:uid` | `LAWYER` — حذف ناعم + تعطيل Auth + نقل الملفات |
| `POST /api/office/users/:uid/transfer` | `LAWYER` — نقل قضايا ومهام مستخدم إلى آخر |
| `POST /api/office/invites` | `LAWYER` — دعوة بالبريد بدل كلمة مرور يدوية |

كل مسار: `requireAuth` + `permit("users.manage")` + `writeAudit`.

### R2 — عزل صارم عند الإنشاء
- `lawyerId` يُؤخذ من توكن المُنشئ حصراً، ويُتجاهل أي قيمة في جسم الطلب.
- `LAWYER` لا يستطيع إنشاء `SUPER_ADMIN` ولا `LAWYER` آخر — يُرفض على الخادم.
- `Custom Claims` تُضبط لحظة الإنشاء.

### R3 — دورة حياة كاملة للحساب
`ACTIVE → SUSPENDED → DELETED(soft) → PURGED(بعد 30 يوماً)`
- الحذف يستدعي `admin.auth().updateUser(uid, {disabled:true})` — **يغلق ثغرة B2**.
- حذف مكتب ⇒ تعطيل كل حسابات مستخدميه + وسم بياناتهم `deletedAt`، مع إمكانية استرجاع كامل خلال 30 يوماً.

### R4 — حدود المقاعد حسب الباقة

| الباقة | محامو مكتب | متدربون | سكرتارية | محاسبون | شركاء/مستشارون | حسابات عملاء (بوابة) |
|---|---|---|---|---|---|---|
| BASIC | 2 | 2 | 1 | 0 | 0 | 0 |
| PRO | 10 | 10 | 3 | 1 | 3 | 25 |
| PREMIUM | لا محدود | لا محدود | لا محدود | لا محدود | لا محدود | لا محدود |

يُفرض على الخادم، ويُعرض في الواجهة كعدّاد "5/10 مقاعد مستخدمة".

### R5 — دعوة بدل كلمة مرور يدوية
- الافتراضي: إدخال البريد ← إرسال دعوة ← المستخدم يضع كلمة مروره.
- **يبقى** خيار "تعيين كلمة مرور الآن" لمن يفضّله، لكن بمولّد كلمات مرور قوية وبعرض لمرة واحدة في نافذة نسخ (لا `alert`).

### R6 — شاشة "فريق المكتب" الموحّدة
صفحة جديدة `/app/team` تعرض كل مستخدمي المكتب بكل الأدوار، مع فلترة ودعوة وتعديل دور وإيقاف ونقل ملفات.
**صفحتا `/app/office-lawyers` و`/app/trainees` تبقيان كما هما** ولا تُحذفان.

### R7 — رقابة `SUPER_ADMIN`
- عمود "آخر دخول" و"عدد المستخدمين" و"عدد القضايا" و"حالة الحساب" في `/app/lawyers`.
- دخول الدعم الفني (Impersonation) عبر Custom Token قصير الأجل، بشريط تحذير ثابت وتسجيل تدقيق إجباري.
